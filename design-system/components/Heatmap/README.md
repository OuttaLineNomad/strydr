A 13-week training-load calendar — the system's one sequential encoding, `heat-1` through `heat-5`, one hue (coral) stepping light to dark. This is the pattern for any "compare magnitude, low to high" chart where color has to carry the value because position can't (a calendar grid, a route's pace-by-segment overlay on the map). It is deliberately **not** built from the six `chart-*` categorical tokens — those are for telling series apart by identity, this is one series at five intensities, and mixing the two systems in one legend would be confusing.

`heat-1` is allowed to fade almost into the surface — that's correct, not a contrast bug. A sequential ramp's lightest step means "near zero," and a rest day should read as *nearly nothing*, the way a blank cell does on a GitHub-style contribution graph. (This is different from an **ordinal** ramp — discrete tiers like funnel stages — where every step must stay independently legible; a sequential ramp like this one is allowed to recede.) In dark mode the direction flips the way you'd expect: `heat-5` gets *brighter*, not darker, so "most activity" still reads as the most prominent cell on a dark surface.

Each cell is a real hit target (14px, well over the usual minimum because cells here sit close together) with its own hover and focus tooltip — per the system's interaction rules, a grid of cells gets per-cell tooltips, never a single shared crosshair the way a line chart does. The legend is a plain five-swatch ramp captioned "Less / More," not a numeric scale — a calendar heatmap's value range changes week to week, so hard-coding numbers on the legend would go stale; the exact mileage is one hover or table-view away. Same "View as table" twin as the other two chart cards, built the same way — DOM methods and `textContent`, never `innerHTML` with concatenated strings, since a series or category label is untrusted input in a real app even when this demo's own data isn't.
