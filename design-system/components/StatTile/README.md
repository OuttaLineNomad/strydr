The dashboard's basic unit — one number a runner actually cares about, in a glass tile.

A hero tile (`metric-hero`, the `display` family at 56px) is for the single most important number on a screen — this week's distance, this run's total time. Everything else is a supporting tile (`metric-lg` or `metric-sm`) in a grid beside or below it. Give every number `font-variant-numeric: tabular-nums` so it doesn't shift width as it updates live.

A trend always reads as a `pill` (`pill--success` / `pill--danger`), never as a bare colored number — the arrow icon and the comparison text ("+0.8 mi vs last week") are both required, so the tile still means something to someone who can't see color. **No sparkline on the tile itself.** An earlier version of this card drew a tiny trend line next to the pill; it came out once this system was checked against real dashboard critique — a chart that small can't carry an axis, a baseline, or a second series, so it either just repeats what the pill's arrow already says or invites a wrong read of the shape. The real trend, honestly drawn with both, lives one tap away on Line Chart or Bar Chart; the tile's job is the number, not a second chart.

**Pill color encodes whether the change is good for *that* metric, not which way the number moved.** `pill--success` and `pill--danger` are named for the outcome, deliberately not `pill--up` / `pill--down` — more distance or more elevation gain is `success` when it rises, but a pace tile showing "+14 sec/mi" is `pill--danger` even though the number went up, because slower pace is the bad direction for that metric. Decide the color by asking "is this better or worse for a runner," never by checking the sign. **Zero or no prior period is `pill--neutral`** (grey, no arrow) rather than forcing a color onto a change that isn't really a change — a first-ever run with nothing to compare against reads "first logged run," not "+100%."

Tiles never stack more than one trend pill, and never show a trend with no comparison period attached (no "+12%" with nothing to say what it's relative to).

**Why the hero number is 56px.** Dashboard research generally finds KPI figures cluster 16–40px, with nothing at 48px or above — Strydr's `metric-hero` sits deliberately outside that range. That research is drawn from admin and analytics screens meant to be scanned in a grid of many numbers at once; Strydr's home screen has exactly one hero stat per view, in the tradition of the fitness apps this brief is modeled on (Strava, Apple Fitness), where a single oversized number *is* the screen's point, not one KPI among many. Kept deliberately — but never add a second number at hero size on the same screen, which is the actual failure mode the research is warning against.
