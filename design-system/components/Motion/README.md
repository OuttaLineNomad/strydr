How glass moves — the interaction layer on top of the Materials card's static recipe. Two demos plus the curve/duration reference table that everything else in this system (including the press demo on the Materials card) pulls from.

**Morph.** Apple's real Liquid Glass shares a `glassEffectID` between two states so the system animates one into the other rather than cutting — a compact icon button growing into a search field is the canonical example, and it works because a circle and a pill are the same shape family (capsule is Liquid Glass's default shape) at two different widths. This card's demo fakes that result with a single `width` transition on `--ease-glass` rather than true shared-element morphing, which is the right tradeoff anywhere that isn't SwiftUI itself — the visual result (one shape growing into another, not a swap) is what matters, not the underlying mechanism. Reuse this pattern for anything that *reveals more* rather than opening a new surface: a filter chip expanding into a filter row, a compact "this week" pill growing into a date-range picker.

**Scroll-responsive chrome.** The tab bar shrinks to icon-only on scroll-down and expands back on scroll-up — `.tabBarMinimizeBehavior(.onScrollDown)` in Apple's own SwiftUI terms. The demo tracks `scrollTop` direction on the scroll container and toggles a `.minimized` class that animates `height`/`padding`/`gap` on `--ease-settle` (no bounce — this is chrome responding to content, not a touched control). Apply the same idea to Strydr's real tab bar once it sits over a scrollable dashboard: never let a floating glass bar permanently cost the content space it sits above.

**The reference table** is the canonical source for every timing value used elsewhere in this system — the Materials card's press demo, `.btn`'s press state, any future component that needs to decide whether it bounces or settles. The rule it encodes: `--ease-glass` (`cubic-bezier(.34, 1.56, .64, 1)`, a controlled overshoot) is for glass responding to a touch — press, release, morph. `--ease-settle` (`cubic-bezier(.22, 1, .36, 1)`, no overshoot) is for everything else that moves — sheets, tab switches, chrome responding to scroll. Keeping those two curves assigned to different *kinds* of motion, never mixed on the same interaction, is what keeps Strydr feeling calm with one bouncy accent rather than either stiff or cartoonish throughout.

**Reduce Motion** is handled once, globally, in `bundle.css` — every duration collapses to near-zero and the overshoot is removed, so glass still changes state under this setting, it just cuts instead of bouncing. No per-component opt-in needed; a new component built from `.glass-interactive` or the `--ease-glass`/`--ease-settle` variables inherits this for free.
